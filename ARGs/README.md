# MURANUCI antimicrobial resistance gene analysis

Downstream analysis of ARIBA–ResFinder and nf-core/funcscan outputs, comparison with cultured isolates, and taxonomic characterisation of ARG-carrying contigs. The main analysis generates manuscript Figures 3–5, Supplementary Figure S7, and supporting CSV tables. It reads existing pipeline outputs and does not execute ARIBA, nf-core pipelines or BLAST searches.

## Directory structure

| Directory | Contents |
|---|---|
| `R/` | Integrated R Markdown analysis |
| `inputs/ariba/` | ARIBA summaries and supporting files |
| `inputs/funcscan/` | Funcscan outputs and harmonized inputs |
| `tables/` | CSV analysis tables |
| `figures/` | Exported figures |
| `supplementary/` | Supplementary tables, sequences and BLAST alignment reports |
| `archive/` | Historical scripts and outputs; not required for the main analysis |

## Data availability

This repository distributes analysis code and documentation. Pipeline inputs, analysis data, manually curated supplementary contig data and the private sample-identifier mapping are not included. Execution requires the files listed below in the local project layout; cloning the repository alone does not provide a complete runnable dataset.

## Required inputs

Paths are relative to the project root, which contains the `metadata/` and `results/` directories.

| File | Purpose |
|---|---|
| `metadata/MURANUCI_sample_id_map.csv` | Mapping of laboratory identifiers to patients and visits |
| `metadata/MURANUCI_culture_metadata.csv` | Culture results and isolate-derived ARG information |
| `results/ARGs/inputs/ariba/out_summary_resfinder.csv` | ARIBA–ResFinder detections |
| `results/ARGs/inputs/funcscan/hamronization_complete_summary_taxonomy.tsv.gz` | Harmonized funcscan results and contig taxonomy |
| `results/TAX-TAXPROFILER/R/clinically_relevant_taxa_all.csv` | Selected bacterial taxa by sample |
| `results/TAX-TAXPROFILER/bracken/table_import_braken_report.csv` | Full Kraken2/Bracken report used for species-level culture comparisons |

The culture metadata contain `patient_id`, numeric `follow_up_week` (0, 1, 2), `province`, `culture_species`, `ST` and `culture_ARGs_raw`. Internal identifiers are held in the private sample mapping; culture records are linked to that mapping by `patient_id` and `follow_up_week`. The mapping is required for local analysis and is not intended for public distribution. The common source identifier is stored in `source_sample_id` within that private mapping. Plot and supplementary-table labels display visits as W0, W1 and W2.

The selected-taxa table is generated by `results/TAX-TAXPROFILER/R/MURANUCI_taxonomy.Rmd` and must be available before running the integrated ARG analysis.

## Dependencies

The analysis loads `tidyverse`. Rendering the R Markdown document also requires `rmarkdown`, `knitr` and Pandoc.

```r
install.packages(c("tidyverse", "rmarkdown", "knitr"))
```

## Run the analysis

From an R session with the working directory set to the project root:

```r
rmarkdown::render(
  "results/ARGs/R/MURANUCI_ARG_analysis.Rmd",
  envir = new.env(parent = globalenv())
)
```

Alternatively, from a terminal at the project root:

```sh
Rscript --vanilla -e 'rmarkdown::render("results/ARGs/R/MURANUCI_ARG_analysis.Rmd", envir = new.env(parent = globalenv()))'
```

The script locates the project root using `metadata/MURANUCI_sample_id_map.csv`. Rendering creates an HTML report beside the Rmd and writes CSV tables to `results/ARGs/tables/` and PNG figures to `results/ARGs/figures/`. Existing outputs with the same names are overwritten.

## Supplementary tables

`supplementary/paper_tables/generate_tables.py` generates supplementary tables from `tables/clinical_ARG_taxonomic_context_summary.csv`, the saved reports in `supplementary/paper_tables/alignment_reports/`, and three local CSV files in `supplementary/paper_tables/curation/`. None of these inputs are distributed in the repository. The curated CSV files contain the selected contig–ARG records, BLAST query definitions and manually reviewed findings and interpretations. See the [curation data documentation](supplementary/paper_tables/curation/README.md) for their columns and editing rules. It uses Python's standard library and does not contact NCBI or execute BLAST.

From the project root:

```sh
python3 results/ARGs/supplementary/paper_tables/generate_tables.py
```

The generator overwrites its supplementary table exports in `supplementary/paper_tables/`.
