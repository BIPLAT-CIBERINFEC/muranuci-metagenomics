# MURANUCI taxonomy and sequencing-depth analyses

Downstream analysis of existing Kraken2/Bracken reports and sequencing quality-control summaries. The scripts generate manuscript Figures 1 and 2 and Supplementary Figures S2–S6, together with supporting CSV tables. They do not run taxonomic classification, quality filtering or host-read removal.

## Scripts

| File | Purpose |
|---|---|
| `R/MURANUCI_taxonomy.Rmd` | Community composition, selected clinically relevant taxa and their read counts and relative abundances |
| `R/MURANUCI_sequencing_depth.Rmd` | Raw and retained read-pair counts and estimated non-host read-pair equivalents |
| `R/functions_taxonomy_plots.R` | Shared palettes, label formatting and plotting functions |
| `R/import_kraken.R` | Import Kraken2/Bracken reports and reconstruct taxonomic lineages |

## Data availability and required inputs

Pipeline outputs, private metadata and generated results are not distributed. Cloning this repository alone does not provide a complete runnable dataset. The local layout is described in the [repository README](../README.md#local-execution-layout).

The following paths are relative to the repository root (`results`):

| Local input | Used by |
|---|---|
| `TAX-TAXPROFILER/bracken/db2/*.report_bracken_species.txt` | Taxonomy analysis |
| `TAX-TAXPROFILER/multiqc_report.html` | Sequencing-depth analysis |
| `../metadata/MURANUCI_sample_id_map.csv` | Both analyses |

The importer expects tab-separated reports without a header, with six columns: percentage, clade read count, directly assigned read count, taxonomic rank, NCBI taxonomy identifier and indented taxon name. Report names must follow the naming convention handled by the scripts.

The private mapping supplies the `source_sample_id`, `name`, `sample`, `patient_id` and numeric `follow_up_week` fields used to associate source reports with manuscript identifiers. The mapping remains outside the public repository.

The sequencing-depth script reads the numeric values stored in the MultiQC HTML General Statistics table. It expects the FastQC/Falco, fastp and Bowtie2 columns and HTML identifiers referenced in the script; reports with a different structure may require adaptation.

## Dependencies

Use the project environment described in the [repository README](../README.md#software-requirements) and restore its recorded packages with `renv::restore()`.

The taxonomy analysis uses `tidyverse`, `ggsci`, `scales`, `cowplot`, `RColorBrewer`, `viridis`, `ggrepel` and `DT`. The report importer also requires `doParallel` and `foreach` and starts 20 worker processes. The sequencing-depth script uses `dplyr`, `readr`, `tidyr`, `stringr`, `purrr`, `rvest` and `ggplot2`. Rendering requires `rmarkdown`, `knitr` and Pandoc.

## Run the analyses

Open `MURANUCI_results.Rproj` or start R in the repository root with the `renv` environment active. Ensure that the inputs are present, then run:

```r
dir.create("TAX-TAXPROFILER/R/PLOTS_TAX_AUTOGENERATED",
           recursive = TRUE, showWarnings = FALSE)
dir.create("TAX-TAXPROFILER/R/PLOTS_TAX_SEQUENCING_DEPTH",
           recursive = TRUE, showWarnings = FALSE)

rmarkdown::render("TAX-TAXPROFILER/R/MURANUCI_taxonomy.Rmd")
rmarkdown::render("TAX-TAXPROFILER/R/MURANUCI_sequencing_depth.Rmd")
```

The analyses can be run independently. Run taxonomy before the integrated ARG analysis when `R/clinically_relevant_taxa_all.csv` is not already available. Rendering creates HTML reports beside the Rmd files. For interactive chunk execution, use `TAX-TAXPROFILER/R/` as the working directory. Existing outputs with the same names are overwritten.

## Generated tables

The taxonomy script writes these CSV files to `R/`:

- `family_global_summary.csv`
- `family_global_summary_paper.csv`
- `family_per_sample_top3.csv`
- `pathogens_summary.csv`
- `dominant_clinically_relevant_taxa.csv`
- `clinically_relevant_taxa_all.csv`
- `selected_taxa_richness.csv`

Family thresholds are based on pooled family-level read counts across the cohort. The selected-taxa tables distinguish percentages within the selected panel from percentages relative to total bacterial-domain reads. These denominators are not interchangeable.

The sequencing-depth script writes `sequencing_read_counts_all_samples.csv` and `sequencing_read_counts_clinical_samples.csv` to `R/PLOTS_TAX_SEQUENCING_DEPTH/`. Non-host read-pair equivalents are estimates derived from fastp read counts and the Bowtie2 host-alignment percentage, rather than direct counts of a non-host FASTQ file.
